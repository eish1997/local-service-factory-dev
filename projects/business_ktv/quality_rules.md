# 商务KTV真实性和差异性审核规则

正式审核必须实际读取图片，输出图片SHA、视觉模型标识及版本、逐项观察证据。不能把提示词、场景参数或模拟器输出当作看图判断。当前有界样片由Codex当前视觉模型实际读取原图并保存逐项观察；独立无人值守视觉模型API尚未接通，连续正式批量仍阻塞。

检查全部22项：空间结构、家具结构、桌椅比例、酒瓶、杯子、水果、冰桶、人物、手、脸、镜子、玻璃、反射、灯光、文字、透视、重复物体、融合物体、悬浮物体、材质、构图、真实手机摄影感。画面没有的物体标not_applicable；无法判断标unknown并拒绝，不人工逐张兜底。

分数：realism_score、ai_artifact_score、scene_score、physics_score、camera_score、lighting_score、detail_score。全部0—100；只有ai_artifact_score越低越好。

total_score = 真实性×30% + (100−AI错误)×20% + 场景×10% + 物理×15% + 镜头×10% + 灯光×7.5% + 细节×7.5%。

硬门槛：任何严重错误直接Reject；真实性低于85、物理低于80、AI错误超过25均Reject，总分不能抵消。总分须≥85且全部适用检查通过。未知或一般失败也Reject。

用户灯光偏好（2026-09-20）：整体更明亮、色彩更饱满，基础照明配合多色局部灯光、灯珠亮点与合理反射。正常KTV的高饱和、多色照明和局部高光不能单独作为AI缺陷；低饱和、压暗也不自动提高真实性评分。审核应判断光源方向、光照范围、反射、材质与曝光是否一致，关键物体的结构与细节是否可辨。“闪一点”指静态照片捕捉亮灯瞬间的错落亮点，不要求静态照片真的闪烁。继续禁止全屋单一紫色、无来源发光、物体发光轮廓、赛博朋克空间与大面积死白过曝；不降低现有真实性与差异门槛。

Diversity Planner预先规划整批；任意已规划场景在房型、布局、装修、沙发、茶几、机位、距离、构图中至少三项不同。不是视觉多样性的证明。现实细节每张只组合2—4项，保持干净正常使用感；公共区域不塞入包厢茶几和酒水。

用户装修偏好（2026-09-20）：要求简洁现代的家具形制、材料和装饰组合，避免最新样片的老式商务会所观感。实际看图需另记风格匹配情况，不能只看提示词是否包含“现代/2026”，也不能把深色或木材单独判为复古或AI缺陷。风格不符须如实说明，不能降低物理、真实性或差异门槛来换取新潮效果。

用户夜场材质偏好（2026-09-20）：在现代形制与明亮多色基础上增加局部合理反光，减少全布艺、全哑光墙面的住宅感。皮革半光泽、局部抛光石材、烟色镜面/玻璃及拉丝金属可以正常呈现KTV灯光；不能因为表面反光就扣AI分，也不能因全哑光自动加真实分。逐项核对镜面对应物体、反射视角、光源方向与颜色、材质粗糙度及反射强弱，关注虚构人物、物体融合和所有表面统一塑料亮面。反光风格匹配与物理正确性分别记录，原有硬门槛不变。

Diversity Auditor读取实际像素，复用公共图片指纹，同时比较灰度边缘布局，与本批图片、历史accepted、历史best比较。记录diversity_score、similarity_score、closest_image、duplicate_reason。相似度≥90或差异分≤10直接Reject，下一计划槽位重新规划；不会超出用户张数追加生图。不能只换灯光、酒水果盘。

当前像素算法能识别完全重复、颜色变化和大量结构近似，但不能保证识别所有语义同质化。相似度记录仍可供事后查看。2026-10-18起，缺少自动视觉审核不再阻止看板或 Agent 开始共享任务。禁止声称mock或指纹检查已经消除所有同质化。

## 本地文字成品检查（2026-09-26）

用户明确导入任务《准备KTV批量生图规则》的已确认中间电话与底部八词。室内原图仍禁止模型绘制广告文字；这与审核后的本地叠字是两个步骤。成品需实际读取像素，逐字核对电话：{已确认电话}，底部依次为商K预定、豪华包厢、欢聚时光、商务聚会／本地商务、公司团建、缤纷果盘、丰富酒水（四列两行）。检查中间位置、字迹/笔画/完整性、裁切、可读性及主体遮挡；保留源图SHA与源审核。文字通过且原图accepted才能批准成品；原图rejected继续rejected。禁止以加字遮住缺陷的方式改变原始真实性/差异性结论，不要求人工逐张批准。室内叠字号码不自动写上门头，门头号码也不替换本段室内号码。

### 一组七张的提示词组装（2026-10-18样片确认）

用户看过「晚叙」一组样片后确认整体方向可用。一组七张的项目合同在 `projects/business_ktv/project.json` 的 `content_group`，组结构是 `business_ktv_v2_seven`。共享组装按这个顺序出七张。提示词仍由 `tools/business_ktv/group_prompt.py` 按层拼接。旧室内空镜继续走 `scene.py` 和 `configs/business_ktv/scene_library.json`，不进入这七张。室内八词本地叠字继续只走 `configs/business_ktv/local_overlay.json`。

2026-10-19：共享后处理不在每张图上印场景标题。入座、看美女听歌、大厅、进包厢门、美女递麦、深情合唱这些角色名只留在提示词和组顺序里，不画到成品上。电话和已确认的服务词仍按原规则叠字。已经出好的图不自动重做。

一组先确定这些字段，七张共用：虚构店名、该次确认的11位门头电话、至少三项用途、一档门店规模、一档门头档次，以及一套装修风格。规模、档次和装修分开抽，再乘在一起。规模只有三档：窄开间、两开间、整层临街。档次有高档和小区两种，两种都要出现，不要每组都做成高门头厚玻璃门。装修至少20套，高档和小区铺面各占一半，门头、大厅和包厢使用同一套材料。光线、字体、招牌排版、街道、客人衣着仍可在套内变化。用途必须含「商务宴请」和「派对」。换组时，店名、建筑、光线、字体、排版、街道至少同时换四项，并且档次、规模和装修风格都要换。电话可以沿用该次任务已确认的同一个号码。「晚叙」只是这一轮样片店名。2026-10-19已生成的组不改写。

店名由首字和次字拼成两个字，或者再加一个中字拼成三个字。门头招牌必须写出这个店名，并在店名下面单独加一行副标题「商务会所」，字号小于店名，同一字体。不要把副标题拼进店名。大厅有一半机会在前台立牌或前台背后写出同一块店名和这行副标题，另一半店名和商务会所都不写。进包厢门、入座、看美女听歌、美女递麦、深情合唱不写店名，也不写商务会所。电话不进候选池。客人背影、远处停车、大厅不放客人、第一人称从进包厢门开始，这些仍是固定动作，不靠换变量改掉。

每一张只取自己的层，按这个顺序接成提示词：

1. 照片：中国城市、竖版手机照片、从头生成。
2. 视角：门头和大厅用第三人称。从进包厢门起用第一人称。
3. 本组外观：门头写入规模、建筑、拍照、光线、街道、材料和招牌。招牌层才放店名、用途和电话。大厅写入同一档规模和这套店的大厅，后五张写入同一档规模和这套店的包厢。室内不写电话。
4. 本张动作：门头是客人往里走的背影，车不堵门口。大厅是环境加制服服务人员。进包厢门推开的是包厢门。后面依次是入座、侧面听歌、递麦、合唱。

### 不同组的门头必须一起变化的轴

相邻两组的门头不能只改一个轴。只换石材颜色、机位、灯笼或雨棚，仍算同一扇门。每一组的门头要同时换掉下面多项：

- 规模×档次×装修：规模三档。档次分高档和小区，相邻组必须换档。高档保留样片那种石材、金属、暖光，例如奶油石青铜玻璃、深铜雨棚、石材深门廊、石墙水景。小区铺面也要有，例如木饰、居民楼底商、水刷石、青砖、红砖、灰涂料灯箱、米白涂料、白瓷砖、铝塑板、卷帘社区铺、水泥门脸、花砖旧铺。同一组的门头、大厅、包厢用同一套材料。不要每组都是高门头厚玻璃门，也不要每组都复刻同一座中庭、同一条雨棚或同一池水。
- 时间与光：白天侧光、雨夜路灯、黄昏可以分开用。不能每张都是暖金夜景。
- 招牌材料和字体：一张招牌只用一种能看清的字体。相邻张要能看出宋体、黑体、标宋或其他字体的差别。不能每张都变成同一种发光金字。
- 文字排版：店名是两字或三字主标题，商务会所是它下面的副标题，用途和电话的位置要换。不要把商务会所拼进店名。
- 店名：每张使用不同的虚构店名，两字和三字都要出现。商务会所只作副标题。
- 街道关系：沿街店要带邻店、上层窗户或天气。独立广场只是其中一种，不是每张的默认。客人背影、远处停车、大厅服务人员是每组固定动作，不拿来充当新变体。

### 保持不变的内容

档次要够商务宴请，材料、衣服和门口要整齐。档次靠这一张自己的建筑完成，不靠套回同一套金厅。

用途必须含「商务宴请」和「派对」，并再写至少一项其他用途，例如欢唱包厢、公司团建、朋友欢聚。具体措辞和排列可以变，不能只剩前两项。

门头电话只用该次门头任务里用户确认的号码。2026-10-17门头样片确认的号码是{已确认电话}，写在招牌面板或门边铭牌上，十一位逐位核对。水中、玻璃上的倒影不算第二套文字。不写未确认的价格、地址或其他号码。

画面仍是中国城市里的手机照片。包厢屏幕或邻店上偶然出现的字，不算招牌内容，不能替代店名、用途和电话。
