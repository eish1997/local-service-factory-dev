# 本地图片看板 1.2.0

测试阶段使用 `dashboard/Start-Development.cmd` 启动源码版。修改后只重启源码版；生成安装包必须先得到用户确认。组装表单必须填写组数和本批次手机号，号码输入默认空白，不自动使用历史号码。

双击 `dashboard/RoadRescueDashboard.exe`。Agent 对话与看板使用同一套本地内容组和任务命令。

## 从提示词到图片

源码测试版采用三栏：左侧项目 → 中间批次 → 右侧内容。中间栏顶部「＋」打开新建表单，必填组数与手机号。右侧顶部图标按钮悬停显示说明；先选组，再查看执行信息并执行。任务选择框确定暂停、继续、重试的目标任务；暂停只停止后续调度，重试仅处理可恢复失败项，均沿用原预算。状态筛选仅改变显示，不改变已选范围，全选始终选择整个批次。

任务状态在顶部全局展示。第二栏顶部可切换“批次 / 提示词”；提示词模式显示当前项目的只读变量，中栏为类型、右栏为详情。切换项目默认回到批次模式。界面使用统一中性深色与轻量选中提示。

项目、批次、组和图片占位可右键删除；项目删除必须准确输入指定文字，操作后无法在应用内恢复。运行中的关联任务必须先暂停并收尾。单图右键“重新组装并生成此图”先展示新提示词和执行范围，点击生成后单独执行，失败保留旧图，成功替换原位置；三拼占位包含三个生成单元。

原“已有图片与待交付”已收为历史批次。标题栏钥匙按钮管理既有渠道与密钥行，不回显原文；与 Agent 共用本机 .env 和私有渠道配置。全局状态显示并发“当前 / 上限”，上限按有效去重密钥数计算，不设固定上限。运行任务期间不允许更改密钥池。

1. 在图片看板选择业务，输入 1–100 个完整组，点击“组装提示词”。
2. 新批次保存到本地后立即显示组卡片；即使没有图片，也可展开阅读和复制各张提示词。
3. 勾选部分组或选择全部组，点击“查看执行信息”，查看待生成数量、复用数量、模型和请求预算。
4. 点击“执行生成任务”即授权所显示范围的已配置 API 生成，不再二次确认。采用自适应整批并发，上限等于有效去重 Key 数量。
5. 图片回填原卡片，生成进度、审核结果与待交付状态分开显示。遇到可恢复失败，可点“继续原任务”；已完成图片不会重新请求。

Agent 组装的批次会自动出现在批次列表；看板创建的任务可以由 Agent 查询和继续。关闭窗口不会中断后台生成。默认视图“已有图片与待交付”保留历史图片，并可读取项目登记来源中对应组的旧提示词；找不到时明确标记。

变量一览仍只读，变量修改请在 Agent 对话中提出。手机号、服务词和业务配置只从本业务的已确认来源读取，不从其他业务或图片中借用。

## 本地数据与生成边界

- 批次：`prompts/library/<业务ID>/<批次ID>/`，保存配置快照、组记录及任务记录。
- 图片：`output/<业务ID>/library/<批次ID>/group_XXXX/`。原图在组内 `raw/`，交付图在组目录；与旧生产组号隔离。
- 新图片加入原待交付状态文件的 `pending_library_groups` 分区，旧 `pending_groups` 保持兼容。
- 相同配置和种子得到一致提示词；生图执行严格使用保存的正文，不在启动时重新随机组装。
- 每个任务单独绑定许可、目标集合、模型、Key 槽位和最多两倍基础请求预算。单图最多两次请求；余额不足在当前任务内隔离槽位，连续接口错误暂停。恢复不新建预算。
- 已返回图片但下载失败、进程中断导致请求结果不确定等情况交由 Agent 检查，避免重复付费；返回地址通过现有私有下载凭据机制保存。
- 新批次组装不调用图片 API；真实执行使用已配置 API。ChatGPT 自带生图仍是 Agent 专属途径，不是看板按钮背后的渠道。

八个业务已接入完整组装。当前本机部分业务缺少已确认电话；开锁和家电的统一服务词配置也需要 Agent 补齐。商务 KTV 已有规则要求实时实际图像审核，未接通后台自动视觉审核通道时继续阻塞无人值守生产，不会绕过审核或生成后自动批准。执行信息会显示具体原因。
