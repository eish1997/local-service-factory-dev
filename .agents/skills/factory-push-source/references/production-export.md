# 原生产目录重新整理到 Git 副本

修改发生在没有 `.git` 的生产目录时读取。先确认开发已经完成，核实源目录、导出脚本和 Git 副本；不要给生产目录额外初始化 Git 绕过现有导出边界。

## 导出快照

先检查本次是否改变了 `development/export_source.py` 的逻辑，再使用它。示例路径按当前电脑替换，目标必须不存在：

```powershell
python development/export_source.py --destination <local-path>
```

脚本拒绝已有目标，只输出脱敏源码，不上传。复用规则白名单和源码脱敏，排除运行状态、客户文件、生产历史、密钥、图片、依赖及安装包。不能用全盘复制或遍历生产输出替代。

## 已验证的脆弱点

- 公开完整性元数据必须与源文件逐字节一致：`dashboard/package-lock.json`、`distribution/requirements-runtime.lock`、`distribution/python-runtime.json`。数字可能属于公开哈希，不能号码清洗。用哈希或字节比较核实。
- dashboard 的 `dist-*`/`release-*` 变体曾混入生产许可。导出需要目录剪枝，不能只排除名为 dist 的目录；检查有限导出文件清单，不搜生产输出。
- 项目 skills 位于 `.agents/skills/`，会被导出；两个发布 skill 还可从个人目录导入。检查当前所有项目技能的入口、引用和 UI 元数据，不写死技能数量，不复制整台电脑 `.codex`。
- 导出的 `agent_memory/current_state.md` 是迁移入口，不能用原电脑客户历史覆盖。生成 README/.gitignore 时也需保留 Git 副本中有效的文档和排除规则。

## 合并差异

两个目录直接比较只能说明差异，不能确定正确版本。先获取远端更新：

1. 找到上次同步提交或快照作为共同基线，区分原目录与 Git/其他电脑改动，用三方或语义合并保留两边功能。
2. 没有基线时检查 Git 历史、内容与用户描述。双方同文件改动无法确定取舍，就展示具体问题并询问，不凭时间戳或生产目录优先决定。
3. 仅复制明确属于本次的新增/修改源码。导出中缺失文件可能被白名单排除、由导出器生成或只存在 Git 副本，不能批量删除、覆盖 `.git`。
4. 源码删除须确认确实已废弃。删除生产项目、任务、图片或数据库不属于本 skill，遵循原授权。
5. 合并后审阅暂存差异，验证入口、公开锁文件与技能，记录同步基线及来源便于下次辨别。

无需清理原生产目录。临时快照可保留复查；若删除，先验证绝对路径确实是本次生成目录，使用 PowerShell LiteralPath，不跨 shell 拼接删除。
